# TBL2 TODO 总览

这组 TODO 的目标，是把当前项目拆成一连串可以独立分配给 agent 的小任务。你可以按编号顺序执行，不建议跳步。

## 推荐顺序

1. `01_环境与规范冻结.md`
2. `02_UART外设.md`
3. `03_Timer外设.md`
4. `04_SoC集成.md`
5. `05_固件与clock_mem.md`
6. `06_测试平台与仿真.md`
7. `07_上板演示与提交物.md`

## 你怎么使用这组 TODO

每个 TODO 都分成四部分：

- `agent 可以做什么`
- `agent 如何实现`
- `你必须做什么`
- `你一步一步怎么操作`

建议你的工作流是：

1. 先打开当前 TODO 文档。
2. 把“agent 可以做什么”那一段原样交给一个 agent。
3. 等 agent 完成后，你按文档里的“你必须做什么”执行必须人工完成的步骤。
4. 确认本 TODO 的“完成标准”满足后，再进入下一个 TODO。

## 当前环境下的现实分工

根据我刚才检查到的本地环境：

- 当前环境可见 `clang`
- 当前环境可见 `iverilog`
- 当前环境没有在 PATH 中看到 `vivado`

因此：

- 代码编写、文件修改、SoC 集成、固件编写、testbench 编写，这些适合交给 agent
- 命令行构建与轻量级仿真，agent 可以先尝试
- Vivado GUI 建工程、综合、实现、烧录 FPGA、打开 Hardware Manager、连接串口、物理接线，这些必须你亲自做

## 交接原则

- 没有完成前一个 TODO，不要急着做后一个 TODO
- 每做完一步，都把改动过的文件和验证结果记录下来
- 如果 agent 的实现和当前 TODO 的接口定义冲突，优先以 `01_环境与规范冻结.md` 里最终确认的规范为准

## 最重要的约束

- 不改 `picorv32.v`
- MMIO 地址尽量直接采用 handout 参考值
- 先做最小可用版本，再考虑加分项
- 先打通 UART TX、timer tick、clock.c，再做美化和扩展功能
