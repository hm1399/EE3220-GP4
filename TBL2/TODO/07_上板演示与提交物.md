把已经完成的软件和硬件整合到 Vivado 工程中，生成 bitstream，上板观察 UART 终端输出，并整理最终提交物。

- 一份可交的提交材料清单
- README / 报告 / AI log 的收尾要求

## 你必须做什么

这一步里，关键事情必须你亲自完成：

- 用 Vivado 建工程或打开课程机工程
- 加入源文件和约束文件
- 设定顶层
- 跑综合、实现、生成 bitstream
- 打开 Hardware Manager 并烧录板子
- 按接线图连接 CH340 与 PYNQ-Z2
- 打开串口终端观察输出
- 把 Markdown 报告转成 PDF
- 最终打包提交

这些步骤要么需要 GUI，要么需要物理硬件，要么需要你本人确认最终提交版本，因此不能完全交给 agent。

## 你一步一步怎么操作

### A. 准备工程文件

1. 确保这些文件已经准备好：
   - `uart.sv`
   - `timer.sv`
   - `picorv32_soc_ref.sv`
   - `pynq_z2_tx_demo_top.sv`
   - `imem.sv`
   - `dmem.sv`
   - `picorv32.v`
   - `pynq_z2_tx_demo.xdc`
   - `clock.mem`
2. 确认顶层模块使用 `pynq_z2_tx_demo_top`

### B. Vivado 里你要做的事

1. 在课程 PC 打开 Vivado。
2. 新建工程或使用已有工程。
3. 加入所有 RTL 文件和 `.xdc` 约束。
4. 确认 `clock.mem` 在工程能被仿真/综合访问到的位置。
5. 设定 top module 为 `pynq_z2_tx_demo_top`。
6. 运行 Synthesis。
7. 通过后运行 Implementation。
8. 生成 bitstream。

### C. 接线和串口

1. 给板子断电。
2. 按讲义连接：
   - `W19 -> CH340 RXD`
   - `W18 -> CH340 TXD`
   - `GND -> GND`
3. 确认 CH340 是 3.3V TTL，不要接 5V/3V3 电源线到 UART 信号脚。
4. 给板子上电。
5. 打开串口工具，设置：
   - `115200`
   - `8 data bits`
   - `no parity`
   - `1 stop bit`

### D. 板上验证

1. 烧录 bitstream。
2. 打开串口终端。
3. 看是否先出现 `00:00:00`。
4. 连续观察至少 3 秒。
5. 如果看不到输出，优先检查：
   - `clock.mem` 是否加载正确
   - 顶层是否选对
   - CH340 TX/RX 是否接反
   - GND 是否共地
   - 波特率是否正确

### E. 提交物收尾

1. 补齐 `README.md`
2. 补齐报告并转成 `report.pdf`
3. 整理 `ai_log.txt`
4. 按 handout 清单打包成 `team_<XX>_submission.zip`

## 你要特别盯住的风险

- 工程里漏加 `clock.mem`
- 顶层选错
- W19/W18 接反
- 串口参数不对
- 只做了仿真，没有做板上演示
- 忘记准备 README、report、ai_log

## 完成标准

- 板上能看到 mission clock 输出
- 至少连续正确走 3 秒
- 交付物清单完整
