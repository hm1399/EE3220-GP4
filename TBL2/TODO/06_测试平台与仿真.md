# TODO 06：写测试平台并做仿真

## 目标

补出 `tb_basic.sv`，并建立一套最小但可信的验证流程，证明 reset、秒进位、分进位、时进位都正确。

## 本 TODO 完成后，你应该得到

- 新文件 `tb_basic.sv`
- 一组可重复运行的基础仿真
- 至少覆盖讲义要求的关键用例

## agent 可以做什么

- 编写 `tb_basic.sv`
- 在 testbench 中实例化 SoC 或顶层
- 对仿真参数做适当缩短，让测试不用等真实 1 秒
- 检查 UART 发出的字符流是否符合预期
- 如果环境允许，用 `iverilog` 做轻量验证

## agent 如何实现

要求 agent 重点完成这些事：

- 文件名：`tb_basic.sv`
- 测试内容至少覆盖：
  - reset 后第一条输出
  - 下一秒输出
  - `00:00:59 -> 00:01:00`
  - `00:59:59 -> 01:00:00`
  - `23:59:59 -> 00:00:00`
- 仿真时允许：
  - 缩短 timer 周期
  - 缩短 UART 分频
  - 用更短字符串等待时间
- 不要求 testbench 很复杂，但要能明确判断 pass/fail

如果 agent 能在本地跑仿真，要求它给出：

- 实际使用的命令
- 通过了哪些 case
- 还没覆盖哪些 case

## 你必须做什么

- 你要确认 testbench 不只是“能跑”，而是真的检查了输出内容
- 如果本地仿真命令与你课程机不同，你要准备在课程机或 Vivado xsim 再跑一遍
- 你要判断当前验证强度是否足够支持上板

## 你一步一步怎么操作

1. 只有在 `uart.sv`、`timer.sv`、SoC 集成、`clock.c` 都已有后，才做这一步。
2. 把本 TODO 交给一个 agent。
3. agent 完成后，先看它有没有覆盖 handout 指定的 5 类行为。
4. 如果 agent 只写了 testbench，但没真正验证输出，要求它补上判定逻辑。
5. 如果 agent 能本地跑 `iverilog`，就让它给你一份通过结果摘要。
6. 测试通过后，再进入 `07_上板演示与提交物.md`。

## 你要特别盯住的风险

- testbench 只打印波形，不判定结果
- 仿真参数和硬件参数混淆
- 没检查 rollover
- UART 字符流检查不完整

## 完成标准

- `tb_basic.sv` 已存在
- 至少覆盖 handout 关键用例
- 有明确的 pass/fail 判断
- 若环境允许，已完成一次本地轻量仿真
